## Commands

```bash
# Install dependencies
bun install

# Start infrastructure (MongoDB, Redis, MinIO S3)
docker compose up -d

# Development server
bun dev

# Production build
bun run build

# Generate Payload artifacts (types + importmap, run in parallel)
bun run generate

# Individual generation
bun run generate:types        # Emits src/payload-types.ts
bun run generate:importmap    # Required after adding admin-facing components

# Database migrations
bun run migrate

# CI sequence (migrate + build)
bun run ci

# Linting and formatting (uses Biome, not ESLint/Prettier)
bunx biome check .            # Check for issues
bunx biome check --write .    # Auto-fix
```

**Testing** — uses the built-in Node.js test runner (no Jest/Vitest):
```bash
node --test                          # Run all *.test.js files
node --test path/to/file.test.js     # Run a specific test
```
Test files must be ESM (`.test.js`). For TypeScript, use `tsx --test` or wrap in thin ESM re-exports.

## Architecture

### Payload CMS + Next.js Integration

Payload CMS is embedded inside Next.js via `withPayload` in `next.config.ts`. The main config is `src/payload.config.ts`, which wires together:
- **Database**: MongoDB via `mongooseAdapter`
- **Cache/KV**: Redis via `redisKVAdapter`
- **Storage**: S3-compatible (MinIO in dev) via `s3Storage` plugin
- **Jobs**: Payload's built-in jobs system for async tasks (cron `* * * * *`, queue `default`)
- **Localization**: `en` (default) + `de` with fallback, timezone `Europe/Berlin`

### Enums and Slugs

All collection, global, and block slugs are defined as TypeScript enums in `src/custom-types.ts`. Always import from `@custom-types` rather than using raw string literals:

```ts
import { CollectionSlug, GlobalSlug, BlockSlug } from '@custom-types'
```

### Resume System

Resume content is split across multiple Globals (`ResumeAboutMe`, `ResumeContact`, `ResumeExperience`, `ResumeProjects`, `ResumeDownloads`, `ResumeCustomers`). The Pages collection has a resume layout that stores block *placeholders*; the `mapResumeValuesToBlocks` `beforeRead` hook dynamically hydrates each block with data fetched from the corresponding Global at read time. This keeps resume data normalized in one place.

Resume PDFs are generated via the `generateResumeDocumentTask` (Payload job) using `@react-pdf/renderer`. Thumbnails are generated by `generateDocumentThumbnailTask`. Both jobs use exclusive concurrency locks with `supersedes: true` to prevent stale queues.

### Collections

Defined in `src/collections/`, exported as `COLLECTIONS` array from `src/collections/index.ts`:
- **Media**: `MediaImages`, `MediaDocuments`, `MediaVideos`, `MediaAudios` — each with S3 prefix and specific hooks
- **Blog**: `BlogPosts`, `BlogCategories` (nested via plugin), `BlogTags`
- **Content**: `Pages`, `ResumeSkills`, `Users`

### Globals

Defined in `src/globals/`, exported as `GLOBALS` array from `src/globals/index.ts`:
- **Resume data**: `ResumeAboutMe`, `ResumeContact`, `ResumeExperience`, `ResumeProjects`, `ResumeDownloads`, `ResumeCustomers`
- **Settings**: `SettingsUserMeta`, `SettingsSiteMeta`, `SettingsHeaderNavigation`, `SettingsFooterNavigation`

### Custom Fields

Factory functions in `src/fields/` that return Payload field configs:
- `AddressField` — group field with geolocation integration (resolves coordinates, region, locality)
- `SlugField` — auto-generates slugs via `beforeChange` hook
- `DocumentKeyField`, `IconField`, `LinkField`, `RichTextField`, etc.

### Jobs & Tasks

Tasks are registered in `payload.config.ts` under `jobs.tasks`. Each task uses `concurrency.key` for exclusive locks. New tasks need importing and adding to that array.

### Admin Panel Customizations

Components in `src/components/AdminPanel/` override the default Payload admin UI:
- Custom `Nav` with footer showing user info
- Umami analytics widgets on the dashboard
- `CellWithThumbnail` for media collections
- Language toggle for localized content
- Resume PDF preview tab in the Pages edit view

After adding any new admin-facing component, run `bun run generate:importmap`.

## Critical Patterns

### Transaction Safety

Always pass `req` to nested Payload operations inside hooks to maintain transaction atomicity:

```ts
// ✅ Correct
await req.payload.update({ collection, id, data, req })

// ❌ Wrong — breaks transaction
await req.payload.update({ collection, id, data })
```

### Hook Loop Prevention

Use context flags to prevent infinite hook loops:

```ts
if (context.skipMyHook) return value
await req.payload.update({ ..., context: { skipMyHook: true } })
```

### Logging

The project has **two loggers** — use the right one:

```ts
// Payload logger — for Payload operations and hooks
payload.logger.info('Message')
payload.logger.error({ msg: 'Failed', err: error })

// Custom OTel logger — for application code with distributed tracing
import { logger } from '@/lib/otel/logger'
logger.info('Message', { context })
logger.error('Message', error, { context })
```

### After Schema Changes

When modifying collections or globals:
1. Run `bun run migrate` to apply Payload migrations
2. Run `bun run generate:types` to regenerate `src/payload-types.ts`

## Code Style

The project uses **Biome** (not ESLint/Prettier) for linting and formatting. Key style settings from `biome.json`:
- Single quotes for JS/TS strings
- Double quotes for JSX attributes
- 2-space indent, 140 line width
- No semicolons (`asNeeded`)
- Trailing commas (`all`)

Import group order enforced by Biome:
1. URL imports
2. Node/Bun built-ins
3. External packages
4. Aliases (`@/*`, `@custom-types`, etc.)
5. Relative paths

## Environment Variables

Copy `.env.example` to `.env.local`. Key variables:
- `DATABASE_URL` — MongoDB connection string
- `PAYLOAD_SECRET` — JWT encryption secret
- `REDIS_URL` — Redis connection URL
- `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` — S3 storage (default endpoint: `http://localhost:9000`)
- `NEXT_PUBLIC_SERVER_URL` — Used for CORS/CSRF and image remote patterns
- `PREVIEW_SECRET`, `CRON_SECRET` — Secrets for draft previews and cron triggers
- `USESEND_*` — Optional email provider (UseSend)
- `UMAMI_HOST_URL`, `UMAMI_WEBSITE_ID` — Optional analytics
