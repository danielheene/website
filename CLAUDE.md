## Project Overview

This is a personal portfolio website built with Next.js 15 and Payload CMS 3. The site serves as both a public-facing portfolio and a CMS-managed blog platform with a resume builder.

**Key Technologies:**
- Next.js 15 (App Router with React 19)
- Payload CMS 3 (headless CMS with custom admin UI)
- MongoDB (database via Mongoose adapter)
- Redis (key-value store for caching)
- S3-compatible storage (media files)
- Tailwind CSS 4
- TypeScript

**Node/pnpm Requirements:**
- Node.js: ^22.0.0
- pnpm: ^10.0.0

## Development Commands

```bash
# Install dependencies
pnpm install

# Start development server (with Turbopack)
pnpm dev

# Build for production
pnpm build

# Start production server
pnpm start

# Generate TypeScript types from Payload schema
pnpm generate:types

# Generate import map for Payload admin
pnpm generate:importmap

# Run both generators
pnpm generate

# Linting
pnpm lint
pnpm lint:fix

# Run Payload CLI commands
pnpm payload [command]
```

## Environment Setup

1. Copy `.env.example` to `.env.local` and configure:
   - `DATABASE_URL`: MongoDB connection string
   - `REDIS_URL`: Redis connection string
   - `S3_*`: S3-compatible storage credentials (access key, secret key, bucket, endpoint, region)
   - `PAYLOAD_SECRET`: Used to encrypt JWT tokens
   - `PREVIEW_SECRET`: Used for draft preview functionality
   - `USESEND_*`: Email service configuration
   - `UMAMI_*`: Analytics configuration (optional)

2. Local development with Docker:
```bash
docker compose up -d  # Starts MongoDB, Redis, and S3-compatible storage (RustFS)
```

3. Seed development data (logged-in users only):
   - Navigate to `/api/seed` to import portfolio data
   - **IMPORTANT:** This endpoint should be disabled in production

## Architecture

### Dual Layout System

The application uses Next.js App Router with two distinct layouts defined by route groups:

1. **`app/(frontend)/`** - Public website
   - Layout: `app/(frontend)/layout.tsx`
   - Includes: Header, Footer, Theme Provider, Analytics
   - Routes: `/`, `/[slug]`, `/posts/[slug]`, `/categories/[slug]`, `/tags/[slug]`

2. **`app/(payload)/`** - Payload CMS Admin Panel
   - Layout: `app/(payload)/layout.tsx`
   - Routes: `/admin/*`, `/api/*` (CMS API endpoints)
   - Auto-generated by Payload

### Payload CMS Structure

All Payload configuration is centralized in `src/payload.config.ts`:

**Collections** (`src/collections/`):
- `BlogPosts` - Blog posts with SEO, nested docs, draft/publish workflow
- `BlogCategories` - Hierarchical categories with nested docs plugin
- `BlogTags` - Flat tag taxonomy
- `Pages` - Dynamic pages with flexible block-based layouts
- `Media` - Media assets with blur hash generation, image metadata, and S3 storage
- `Users` - Admin users with role-based access

**Globals** (`src/globals/`):
- `SettingsHeader` - Site-wide header configuration
- `SettingsMeta` - SEO metadata templates
- `Resume*` - Resume sections (AboutMe, Contact, Customers, Downloads, Experience, Projects)

**Blocks** (`src/blocks/`):
- General: `LinkGroupBlock`, `OneColumnContentBlock`, `TwoColumnContentBlock`
- Resume-specific: `ResumeAboutMeBlock`, `ResumeContactBlock`, `ResumeCustomersBlock`, etc.
- Blocks enable flexible, composable page layouts

**Fields** (`src/fields/`):
Reusable field configurations:
- `RichText` - Lexical editor with custom toolbar
- `Link` - Link field with internal/external support
- `Slug` - Auto-generated slugs
- `Title`, `TagList`, `LinkGroup`, `CustomerLogos`, `JobHistory`, `ProjectList`

### Image Processing Pipeline

When images are uploaded to the Media collection:
1. Blur hash is generated for placeholder images (`generateBlurDataURL` hook)
2. Alt text is auto-generated if not provided (`generateAlt` hook)
3. Images stored in S3-compatible storage with CDN delivery
4. Thumbnails generated automatically (500x500 cover)
5. SVG logos are sanitized and adapted via internal API (`/api/svg-adapter`)

### Path Aliases

Defined in `tsconfig.json`:
- `@/*` → `./src/*`
- `@imgs/*` → `./public/payload/blocks/*`
- `@payload-config` → `./src/payload.config.ts`
- `@payload-types` → `./src/payload-types.ts`
- `@custom-types` → `./src/custom-types.ts`
- `@styles/*` → `./src/styles/*`
- `@fonts/*` → `./public/fonts/*`

### Custom Admin Panel Components

Custom Payload admin UI components in `src/components/AdminPanel/`:
- `Nav` - Custom navigation with grouped collections
- `Widgets` - Dashboard widgets (e.g., `DummyWidget`)
- Logo/Icon customization

### Resume PDF Generation

Resume can be generated as PDF via `/api/resume-pdf` route using `@react-pdf/renderer`. PDF templates are in `src/pdfs/ResumeDocument/`.

## Notable Implementation Details

### Content URL Generation
Use `generateContentURL({ collection, slug })` utility to generate URLs for collections. This ensures consistency across SEO, navigation, and links.

### Lexical Rich Text Editor
Configured in `src/payload.config.ts` with custom toolbar groups:
- Text formatting (paragraph, headings, lists, blockquote)
- Inline formatting (bold, italic, underline, strikethrough, code)
- Alignment, indentation
- Links, relationships, uploads, tables

### Storage Configuration
Uses S3 storage plugin with configurable endpoint (supports RustFS for local dev, or any S3-compatible service for production).

### Access Control
Custom access functions in `src/access/`:
- `authenticated` - Requires logged-in user
- `anyone` - Public access

## Type Generation

After modifying Payload collections, globals, or fields:
```bash
pnpm generate:types
```
This updates `src/payload-types.ts` with TypeScript types for type-safe data access.

## Custom API Endpoints

Payload endpoints defined in `src/payload.config.ts`:
- `/api/seed` - Seeds development data (remove in production)

## Styling

- Global frontend styles: `src/styles/frontend.css`
- Payload admin styles: `src/styles/payload.css`
- Tailwind CSS 4 with custom theme in `src/styles/theme/`
- Uses next-themes for dark/light mode

## Data Flow

1. Content creators use Payload admin panel (`/admin`) to manage content
2. Collections/Globals are stored in MongoDB
3. Redis caches frequently accessed data
4. Frontend fetches content via `getPayload()` or GraphQL
5. Pages are statically generated or server-rendered based on route configuration
6. Media served from S3-compatible storage

## Special Features

- **Nested Docs Plugin**: Used for hierarchical blog categories
- **SEO Plugin**: Auto-generates meta tags with custom title templates
- **Live Preview**: Configured breakpoints for mobile/tablet/desktop preview in admin
- **BlurHash**: Placeholder images generated on upload for better UX
- **SVG Adaptation**: Client logos sanitized and themed via internal API
- **Umami Analytics**: Privacy-focused analytics with proxy rewrites
